# bitplane Command Center

A desktop app for working with bitplane planes: a sidebar of planes and tabbed terminal sessions rooted in each plane. Built with Tauri 2, React and wterm (Ghostty core).

The v1 spec is the source of truth for behaviour; vocabulary lives in [`GLOSSARY.md`](GLOSSARY.md) and decisions in [`docs/adr/`](docs/adr/).

## Requirements

- macOS, or Linux x64/arm64 with WebKitGTK
- `bp` 0.1.0 or newer on your login shell's `PATH`
- Node 26 (`.nvmrc`), pnpm 12, and the Rust toolchain pinned in `rust-toolchain.toml`

## Sessions and agents

Sessions run in the bundled session daemon, `bitplane-sessiond`: quitting cc leaves them running, and the next launch reattaches every tab, scrollback included. Each tab shows the state of the Claude Code session running in it (idle, busy, waiting, resuming, exited), with nothing installed in `~/.claude/settings.json`. When the daemon itself restarts, tabs come back with fresh shells and their Claude Code sessions resumed. To pick up a Claude Code session that has exited, run **Resume agent session …** from the palette (⌘P).

If a tab says agent hooks didn't load, your shell's rc files probably rebuild `PATH` and bypass the daemon's `claude` wrapper; the agent's state then lags a few seconds.

The first launch after upgrading from a cc without the daemon reopens its old tabs, resuming their Claude Code sessions, and removes the old cc's hooks from `~/.claude/settings.json`.

## Development

```sh
pnpm install
pnpm dev     # run the app
pnpm check   # typecheck, lint, format check, all tests: the gate before committing
```

`src/ipc/bindings.ts` is generated by tauri-specta whenever a debug build starts. To regenerate it without starting the app: `UPDATE_BINDINGS=1 cargo test --manifest-path src-tauri/Cargo.toml --test bindings`. A `cargo test` fails while the committed copy is stale.

## Troubleshooting

- **Blank window on Linux (some NVIDIA setups):** start the app with `WEBKIT_DISABLE_DMABUF_RENDERER=1`. The app doesn't set it itself.
- **bp not found:** the app looks for `bp` on the `PATH` your login shell sets up (`$SHELL -l -i`), not on the GUI's `PATH`.
