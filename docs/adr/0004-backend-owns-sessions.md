# The Rust backend owns plane and session state; a reload reattaches

The backend holds the authoritative list of planes, draft planes, in-flight creates and sessions (with their PTYs). The React frontend is a mirror: it loads a snapshot and then follows full-state events. It keeps only UI state of its own, such as the selection, the active tab and which tree nodes are expanded. A webview reload, which happens only in dev or after a WebContent crash because ⌘R is swallowed, therefore reattaches to the running sessions instead of killing them. The terminals come back blank, and a resize prompts full-screen programs to redraw. Two alternatives were rejected. Reaping orphaned PTYs on reload (terax-ai's approach) loses work. Replaying an output ring buffer can restore a garbled screen, for example when the replay starts mid escape sequence or the alternate-screen state is lost.
