# Use @pierre/diffs for File tabs

File tabs render diffs and plain files with `@pierre/diffs`, from the same company as `@pierre/trees` (ADR 0007). It takes a raw `git diff` patch, which is what the backend produces anyway (ADR 0006), can load both full sides on demand so unchanged context expands, highlights with Shiki, and does unified and split layouts with word-level changes; t3code runs the same version next to trees in production. It ships its own renderer, so it shares nothing with trees beyond theming, and costs about 145 kB gzipped, so it is lazy-loaded with the first File tab, and Shiki grammars load per language. Breaking changes have landed in minor releases, so the version is pinned exactly at 1.5.2, and everything goes through our `DiffView` wrapper (`src/file-tab/DiffView.tsx`), the only module that imports it. `DiffView` also highlights the Markdown preview's code blocks (`highlightCode`), so the lazy `MarkdownView` chunk pulls it in. Like trees, it renders in a shadow DOM and is themed through its `--diffs-*` properties, mapped from `theme.css` in `src/ui/pierreTheme.module.css`, the theme file both libraries share.

`enableGutterUtility` must stay off: drag-selecting with it crashes WKWebView, which Tauri uses on macOS (pierre#1184, fix closed unmerged). The parser has no binary handling, so the backend detects binary files with `--numstat` before asking for a patch, and a patch that doesn't parse shows as raw text. Research: the answer of "Diff view on file click" (#23).
